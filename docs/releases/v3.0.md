# Checkpoints v3.0 — release note (draft, not yet released)

Student features:
- **Java track** (fourth language): 44 checkpoint exercises in 3 checkpoints × 5 levels, as in the program (list.json, D34). Official subjects, tests and harness, unchanged; Run compiles and runs ExerciseRunner, Submit runs the official JUnit test. Hints for every exercise.
- **Mock exam**: pick a track and checkpoint, set the time in hours; one level at a time, the next opens only after a pass; a top bar with the timer; the report shows only the levels the student saw.
- **Hints** for every exercise (Go 60, JS 29, Rust 40, Java 44), closed during exams.
- **Expected vs got card** when a test fails (Go, JS, Rust, Java).
- **Command palette, keyboard shortcuts, focus mode, breadcrumbs, next-exercise prompt.**
- **About**: thanks to Ali Alsaroo (@aalsaroo).

Fixes:
- Rust: code submitted within a second of the previous build could be graded on that previous build. Files are now re-stamped before cargo runs.
- Migrations rebuild tables with foreign keys off (SQLite's procedure), keeping every row.

Checks before release: lan_vm1 server 45/45 tests, web 141/141; parity Go 60/60, JS 29/29, Rust 40/40 (3 runs); Java image 132/132 and Cloud Run wrapper 133/133; self-audit pass (`docs/audits/v3.0-2026-11-04.md`).

## Deploy (waiting for the owner's local test and approval)
1. Back up the production DB on the VM (`make backup`).
2. Build the Java Cloud Run image from `docker/runner-java/cloudrun` and create the service like Go/JS: min-instances 0, a small max, concurrency 1, ~1 GiB; private (ID-token auth from the app's VM). Put its URL in `.env.vm` as `RUNNER_JAVA_CLOUDRUN_URL`.
3. `LEGACY_REDIRECT=0 make deploy`: migrations 006_exams and 007_java.
4. Check: health, `/api/java/exercises` 401 without sign-in, one Java Run/Submit, one Rust Submit; old sites still 200 (D21).
