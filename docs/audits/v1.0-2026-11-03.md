## Security review (server/src)
- Dev login: 404 unless `appEnv !== 'production'` (`config/index.ts:132`, `routes/index.ts:194`). See F2.
- Session cookie: HttpOnly, SameSite=Lax, Path=/, Secure in production (`middleware/http.ts:68-74`). Token stored as SHA-256.
- Files: `pickEditorFiles` accepts only names in `ex.editorFiles` (512 KiB each) (`services/exercises.ts:243`), so no traversal.
- Args: at most 32, each length capped (`routes/index.ts:479-486`). JSON body capped at 256 KiB (`middleware/http.ts:25`). nginx caps the body at 2m.
- Run WebSocket: checks that the run belongs to the caller (`routes/run-socket.ts:24`). Cancel checks the owner (`dispatcher.ts:295`). Terminal: needs a signed-in caller and uses that caller's own container.
- Docker: NetworkMode none, CapDrop ALL, memory = swap, PidsLimit, no-new-privileges flag, never privileged (`ephemeral.ts:85-94`, `rust.ts:120-127`). See F3 for the Go read-only root.

## Findings
### F1 — Clean checkout cannot run `make setup` on the VM
- **Severity:** blocking (fixed check 1)
- **Rule:** self-audit.md check 1; release.md definition of done "Runs from a clean checkout"
- **Evidence:** `Makefile:19` setup fails with `.env and .env.example are both missing`. `.env.example` is tracked at 0ce0207, but the `make send` copy leaves it out (it excludes `.env*`).
- **Impact:** the documented setup fails from the audited clean copy.
- **Fix:** make `make setup` fall back to built-in defaults when `.env.example` is absent, or ship it under a name that send keeps (e.g. `config/env.example`). Then re-run check 1.
- **Goes to:** `release.md` step 10

### F2 — Dev login fails open when APP_ENV is unset
- **Severity:** minor
- **Rule:** core.md (secure defaults), level V1
- **Evidence:** `server/src/config/index.ts:20` default `appEnv: 'development'`; `:132` enables dev-login whenever appEnv is not `production`. Only `deploy/systemd/checkpoints.service:14` sets production.
- **Impact:** a deploy that skips the unit file's environment (or misspells it, e.g. `prod`) exposes sign-in as any username.
- **Fix:** enable dev-login only when `APP_ENV` is exactly `dev`/`development` or `test`, and refuse to start with an unknown value.
- **Goes to:** V2 in `versions.md` (or step 10 if the owner prefers)

### F3 — Go run container has a writable root filesystem
- **Severity:** minor
- **Rule:** brief: runner read-only, level V1
- **Evidence:** `server/src/services/runner/go.ts:93` `readonlyRootfs: false` (an exec tmpfs is already mounted at :91).
- **Impact:** student code can write to the container root (but there is no network and the container is thrown away).
- **Fix:** set `readonlyRootfs: true` and point GOCACHE/GOTMPDIR at the tmpfs; re-run Go parity.
- **Goes to:** V2 in `versions.md`
